# `archi.md` — s2ctl

> Архитектурный контракт репозитория. Кратко: границы, ограничения, контракты.
> Межрепозиторные рёбра — только в `workspace.yaml` корня workspace.

## 1) Context ID / Owner / Repository mapping

| Context ID | Owner | Repository | Code paths |
| --- | --- | --- | --- |
| ctx_cli_s2ctl | team/backend (не подтверждён) | s2ctl | src/s2ctl, src/ssclient, tests, bundle, docker |

Owner проставлен допущением при заведении файла и владельцем не подтверждён:
у репозитория нет CODEOWNERS, а карточка TSK0003840 пришла из эпика Public API.
Значение требует подтверждения человеком.

Репозиторий одноконтекстный: CLI и его клиентский слой — один контекст,
инфраструктура сборки бинаря (`bundle/`, `docker/`) принадлежит ему же.

## 2) Boundaries (in/out of scope)

- In scope: команды CLI и их справка (`src/s2ctl`), клиентский слой контракта
  `public-api` (`src/ssclient`), локальный конфиг и контексты (ключи проектов
  в keyring), ожидание асинхронных задач платформы, сборка единого бинаря
  для Linux и Windows.
- Out of scope: доменные правила и валидация услуг (владелец — `cloudmng`);
  остальные внешние API монолита (`partner-api`, `referral-api`, Admin API v3);
  генерация клиентского слоя из OpenAPI — слой рукописный.
- Primary L1 context: `ctx_cli_s2ctl`; Affected L1 contexts: нет.

## 3) Layering constraints

- Слои: `ssclient` → `s2ctl`. `ssclient` — HTTP к `public-api`, пути, payload'ы
  и разбор ответа; `s2ctl` — разбор аргументов, вызов сервиса, вывод.
- Разрешено: `s2ctl.cmd_*` получает сервис фабрикой `ssclient.client`
  и печатает результат через `echo`/`FORMATTERS` из `s2ctl.click`.
- Запрещено: HTTP-вызов и разбор ответа в `cmd_*`; импорт `s2ctl` из `ssclient`
  (обратная зависимость слоёв); `print` и построчная сборка ответа в обработчике
  команды; группа команд без регистрации в `src/s2ctl/__init__.py` — в бинарь
  попадает только то, что импортировано оттуда.

## 4) External contracts (API/events)

| Contract | Type | Direction | Owner | Compatibility |
| --- | --- | --- | --- | --- |
| `public-api` — REST монолита | API | in | cloudmng | consumer: CLI следует за publisher'ом и своего контракта не определяет |
| поверхность CLI — имена команд, аргументов и форматы вывода | CLI | out | ctx_cli_s2ctl | имена и аргументы существующих команд не меняются: на них написаны пользовательские скрипты |

Локальный конфиг и keyring — не контракт: приватное состояние машины пользователя.

## 5) Quality gates and testing

- Tests: клиентский слой — `tests/ssclient/**` по образцу `test_http_client.py`
  (локальный `aiohttp`-сервер из `tests/conftest.py`: метод, путь, payload,
  разбор ответа) — Required; слой команд — `tests/s2ctl/**`, состав дерева
  команд и разбор аргументов — Required; для команды, чьё тело запроса —
  подмножество полей request-DTO контракта (одна операция контракта разведена
  на несколько команд), Required и проверка «опция команды → поле запроса
  контракта»: тело несёт каждое обязательное поле операции, и недостающие
  значения команда добирает сама, а не перекладывает на пользователя;
  соответствие «операция контракта → команда» —
  `tests/s2ctl/test_command_coverage.py`, Required: команда без места в таблице
  и операция в объёме без команды роняют прогон; инварианты дерева команд —
  `tests/s2ctl/test_cli_tree.py`, Required: состав групп, `--output` у каждой
  команды, парность «печатает ссылку на задачу ↔ несёт `--wait`», описание
  у команды и `help` у опции. Инварианты проверяются обходом дерева, а не
  перечислением, поэтому новая команда попадает под них сама; сам текст
  справки не проверяется, тестов на форматтеры не создавать.
- Gates: `poetry install`; `make test` (pytest, покрытие `src`; тот же прогон
  несёт тест покрытия контракта и инварианты дерева команд); `flake8 src`
  (wemake-python-styleguide, конфиг `.flake8`); `make pyright`
  (`pyright ./src`, конфиг `[tool.pyright]` в `pyproject.toml` — тот же гейт
  запускает шаблон CI); `make test-tox` (матрица py311, py312, py313);
  `bash bundle/build_linux.sh` (единый бинарь).
- Done: гейты зелёные; новая группа команд зарегистрирована
  в `src/s2ctl/__init__.py`; у read-команды есть `--output`, у асинхронной —
  `--wait`; новая операция контракта внесена в таблицу покрытия и в README;
  новое подавление в `.flake8` или `pyright` — с обоснованием.

## 6) Known legacy deviations

| Deviation | Impact/Risk | Mitigation plan |
| --- | --- | --- |
| `server power-off` и `server reboot` переключаются флагом `--hard` между парами операций API (`power/shutdown`↔`power/off`, `power/reboot`↔`power/reset`) | нарушение GR-01: флаг меняет смысл команды; на новые разделы не тиражируется (VMware-питание — 5 отдельных команд) | смягчено: `power/shutdown` и `power/reset` получили свои команды (`server shutdown`, `server reset`), у `--hard` в справке сказано, что делать вместо него. Сами флаги остаются: смысл существующих вызовов менять нельзя. Своей команды нет только у `power/off` — под неё нужно имя, не занятое легаси-командой; вопрос имени решается с владельцем поверхности CLI |
| Состав команд собирается импортами в `src/s2ctl/__init__.py` (подавления WPS412, WPS235) | забытый импорт = команда есть в коде, но отсутствует в бинаре, и обнаруживается только вручную | тест дерева команд `tests/s2ctl/test_cli_tree.py` — обязательное дополнение при каждой новой группе |
| Раздел Kubernetes контракта `public-api` (16 операций) в CLI не поддержан, хотя маршруты опубликованы | паритет CLI с контрактом неполный: кластерами управляют только панель и прямые вызовы API | поддержать разделом целиком, когда он войдёт в опубликованный справочник API и сервис `feature-k8s` выйдет из режима поддержки; до тех пор отсутствие команд удерживает тест покрытия — «частичной» поддержки быть не должно |
| `ServerId` (`l{n}s{n}`) доменного типа не имеет: id сервера ходит в сигнатурах группы `server` строкой | нарушение GR-02: формат id проверяет только API, перепутать местами id сервера и сети типы не мешают. TSK0003840 не только не устранила отклонение, но и добавила на нём новые сигнатуры — `ServerService.set_configuration` и `.rename` | завести тип с фабрикой и мигрировать группу `server` (28 команд) отдельной карточкой: правка механическая, но задевает весь раздел, а новые операции этой задачи обязаны были встать рядом с существующими |
| `ssh_keys` в заказе VMware-сервера остаётся `Sequence[int]`, хотя прочие id раздела — обёртки `NewType` (`ssclient/vmware/ids.py`) | собственного типа идентификатора SSH-ключа в репозитории нет — обернуть здесь нечего; риск перестановки при этом отсутствует и без обёртки: поле лежит рядом с `location_id`, `image_id` и `public_network_id`, но `Sequence[int]` со скалярным id несовместим по типам | завести общий тип идентификатора SSH-ключа вместе с типизацией группы `ssh-key` — отдельной карточкой |
| Пайплайн описан внешним шаблоном `b2c/ci` (`s2ctl/pipeline.yml`, `ref: v1.0.0`), несовместимым со стеком после подъёма зависимостей: `image: python:3.8`, `POETRY_VERSION: "1.0.*"`, `.build_nix` с `poetry install --no-dev` | локальные гейты зелёные, а пайплайн MR не поставит зависимости и не соберёт бинарь; правка лежит вне этого репозитория | развилка за владельцем: бампнуть шаблон в проекте `b2c/ci` отдельной карточкой либо перенести пайплайн в `s2ctl`. До этого гейтом остаётся локальный прогон |
| Удаления `ssh-key delete`, `server delete-tag`, `network delete-tag` и `gateway delete-tag` не отдают ссылку на задачу и потому не несут `--wait` | у этих четырёх команд вывод пуст, и связать удаление с задачей скрипт не может; у остальных десяти DELETE-операций контракта `--wait` есть | не отклонение CLI, а граница контракта: `return_task` эти маршруты publisher'а не объявляют вовсе (`SshKeysController.Delete`, `Unmark`-действия) и отвечают пустым 200. Пересмотреть, если publisher начнёт отдавать по ним задачу |
| `vmware edge upsert-nat-rule` и `upsert-vpn-tunnel` выбирают между созданием и правкой по наличию `--rule-id` / `--tunnel-id` | формальный признак GR-01: необязательное поле меняет смысл операции | оставлено намеренно: у publisher'а это один маршрут (`POST .../edge/nat`, `POST .../edge/vpn`), он сам называет операцию Upsert и правило задаёт целиком. Разведение на `create-*`/`update-*` завело бы две команды на одну операцию контракта и разошлось бы с таблицей покрытия; пересмотреть, если publisher разделит маршруты |
| Типовой гейт `pyright` заведён на легаси-коде и в двух местах закрыт подавлениями: динамический `Literal` из enum в `ssclient/domain/record_entities.py`, сужение `Optional` в `s2ctl/cmd_sshkey.py` | гейт зелёный, но эти два места типами не описаны | снять подавления вместе с переработкой типов записей DNS — отдельной карточкой |
| Образы сборки (`docker/Dockerfile.*`) и CI (`.gitlab-ci.yml` → внешний шаблон `b2c/ci`) не воспроизводятся локальными гейтами | расхождение локальной сборки и пайплайна ловится только запуском пайплайна в MR | держать `bundle/build_linux.sh` единственной точкой сборки, образ — только окружением для него |

## 7) Change policy and required reviews

- Policy: новая операция контракта = отдельная команда (GR-01), а не флаг-режим
  у существующей; имена и аргументы существующих команд не меняются;
  `pyproject.toml` и `poetry.lock` правятся парой.
- Required reviews: владелец контекста; интеграции — при добавлении раздела
  контракта `public-api` в CLI.
- Escalation triggers: изменение имени или аргумента существующей команды;
  обращение к API, отличному от `public-api`; HTTP-вызов в обход `ssclient`;
  расширение `per-file-ignores` в `.flake8` без обоснования.
