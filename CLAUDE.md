# s2ctl — CLI Public API

Python-клиент того же контракта `public-api`, что и Go SDK: серверы, сети, DNS,
шлюзы, VMware Cloud, ansible-инвентарь. Один бинарь для Linux на все бренды
платформы — хост API выбирается по префиксу ключа проекта
(`HOSTS_MAP` в `src/s2ctl/client.py`) либо ключом `host` в `config.yaml`.
Дефолтная ветка — `origin/master`.

Границы, слои, внешние контракты и отклонения — `archi.md` рядом.

## Стек

Python 3.11+, poetry (lock версии 2.0, группа dev — `[tool.poetry.group.dev.dependencies]`),
click 8, aiohttp 3.14, tabulate, PyYAML, keyring + `keyrings.cryptfile`,
pyinstaller 6 для бинаря.

## Структура

| Путь | Что там |
|---|---|
| `src/ssclient/` | клиентский слой: HTTP к `public-api`, пути, payload'ы, разбор ответа, ожидание задач. Про click и вывод не знает |
| `src/s2ctl/` | слой команд: разбор аргументов, вызов сервиса, вывод. `cmd_<раздел>.py` — по разделу контракта |
| `src/s2ctl/__init__.py` | реестр состава CLI: группа, не импортированная сюда, в бинарь не попадает |
| `tests/ssclient/`, `tests/s2ctl/` | тесты клиентского слоя и команд соответственно |
| `bundle/` | сборка единого бинаря (`build_linux.sh`, `bundle.py`) и публикация релиза в GitHub (`release_github.sh`) |
| `docker/` | образ окружения сборки: `Dockerfile.linux.py311` (glibc 2.28) |
| `.gitlab-ci.yml` | пайплайн проекта: гейты стадии `test`, сборка бинаря на `build` и `prod`, публикация релиза в GitHub на `prod` |

## Перед сдачей изменения

```sh
poetry install
make test                 # pytest с покрытием src
make lint                 # flake8 src tools: wemake-python-styleguide + порядок
                          # импортов (isort), конфиг .flake8 и [tool.isort]
                          # в pyproject.toml
make pyright              # pyright ./src — тот же гейт гоняет пайплайн
make test-tox             # матрица py311, py312, py313
bash bundle/build_linux.sh
```

Пайплайн лежит в самом репозитории (`.gitlab-ci.yml`, внешних `include` нет)
и на стадии `test` гоняет те же три гейта целями `Makefile` — `make test`
матрицей по py311, py312 и py313, `make lint`, `make pyright`. Стадия `build` собирает бинарь
на ветке, `prod` — по тегу `vX.Y.Z` и публикует его в GitHub Releases
`itglobalcom/s2ctl`.

## Релиз

Мерж в `master` бинарь не выпускает. Релиз — тег `vX.Y.Z` на коммите `master`,
annotated-сообщение тега становится описанием релиза:

```sh
git tag -a vX.Y.Z -m "<что изменилось для пользователя>" origin/master
git push origin vX.Y.Z
```

Пайплайн тега собирает архив и job'ом `prod_release_github` публикует его
в GitHub Releases; в проекте должна быть CI/CD-переменная `GITHUB_TOKEN`
(protected, masked) с правом `contents:write` на `itglobalcom/s2ctl`.
Повторный запуск job'а заменяет архив релиза, а не создаёт второй.

## Конвенции

- **Одна операция контракта = одна команда.** Флаг, переключающий команду между
  двумя маршрутами API, не заводится, и имя команды называет ту операцию,
  которую она вызывает: пять переходов питания — пять команд в обоих разделах,
  vStack и VMware. Обратное тоже бывает: если один маршрут меняет две
  независимые вещи, он разворачивается в две команды (`vmware network rename`
  и `set-bandwidth`).
- **Новая операция контракта попадает в три места:** метод сервиса в `ssclient`,
  команда в `s2ctl`, строка в `tests/s2ctl/test_command_coverage.py` и в таблице
  покрытия README. Тест покрытия падает и на команде без операции, и на операции
  без команды.
- **Знаменатель покрытия — снимок маршрутов `tests/s2ctl/contract_operations.txt`,**
  а не список в тесте: таблица покрытия сверяется с ним построчно. Снимок снят
  с исходников publisher'а и в заголовке несёт ревизию, на которой снят.
  Поднять его — отдельный осознанный шаг вместе с подъёмом ревизии контракта:

  ```sh
  python tools/dump_contract_operations.py <путь к рабочей копии cloudmng> \
      > tests/s2ctl/contract_operations.txt
  ```

  Инструмент разбирает `[Route]` контроллеров и `[Http*]` их действий в
  `Com.Cloudmng.Api.Public/Controllers/**` и раскрывает пути, заданные
  `const string`: разбор одних строковых литералов теряет три операции
  (чтение и удаление affinity-группы, `GET /api/v1/tasks/already_completed_task`)
  и занижает счёт — на этом обожглась постановка задачи. Нераскрытая ссылка
  на константу и два маршрута, схлопнувшиеся в одну строку снимка, разбор роняют,
  а не пропускают. Новые строки снимка без команд роняют тест покрытия — это
  и есть объём работы по новой ревизии контракта.
- **Новая группа регистрируется импортом в `src/s2ctl/__init__.py`** и вносится
  в `tests/s2ctl/test_cli_tree.py`. Иначе команда работает из исходников
  и отсутствует в бинаре.
- **Составной id — доменный тип с фабрикой** (`NetworkId`, `GatewayId`,
  `AffinityGroupId`, `ServerId`: `try_parse` + шаблон формата), а не строка
  в сигнатуре.
  Тип живёт в своём модуле `*_id.py`; на границе click его получают колбэком
  параметра из `s2ctl/params.py` — единственного места, где такие колбэки
  заводятся, — и неверный формат отсекается до запроса.
- **Числовой id раздела VMware — обёртка `NewType`** из `ssclient/vmware/ids.py`:
  проверять в значении нечего, но в сигнатуре их по два-три, и `int` не мешает
  переставить их местами. В рантайме обёртка — тождество, поэтому на границе
  click тип объявляется аннотацией параметра команды, а не колбэком; в остальных
  местах (разбор ответа, `resources[]` задачи) значение оборачивается явно.
- **Общий query — `with_filters`** из `ssclient/base.py`: собирать строку запроса
  в сервисе руками не нужно, пустое значение объявленного параметра publisher
  не принимает.
- **Опции — общие декораторы:** `output_option` (`--output yaml|json|table`)
  у любой команды, печатающей результат; `wait_option` (`--wait` и парная
  к нему `--timeout`) у команды асинхронной операции; `rules_file_option` —
  там, где набор правил заменяется целиком. Таймаут ожидания задачи опция
  кладёт в `ssclient.task_wait.TASK_TIMEOUT_SECS` — контекст вызова, а не
  аргумент конструктора: нужен он в глубине ожидания задачи, и параметром его
  пришлось бы тащить через каждую операцию каждого раздела. Команда печатает
  через `echo` из `s2ctl.click`, `print` не используется; `echo` печатает пустую
  коллекцию документом машинного формата (`[]`, `{}`), а `None` — ничем.
- **Сервис создаётся вызовом команды, а не разбором её группы:** колбэк группы
  несёт только описание, а `client_factory` зовёт аксессор сервиса в теле
  команды. Клиент, созданный в колбэке группы, требовал бы ключ API на
  `s2ctl <группа> <команда> --help` — click выполняет группу раньше, чем
  доберётся до самого `--help`. Инвариант держит
  `test_help_of_every_command_needs_no_api_key`.
- **Удаление, у которого publisher отдаёт задачу, ходит через
  `with_return_task`** и несёт `--wait`: без параметра ответ пуст. Задачи нет
  у четырёх маршрутов — `ssh-key delete` и три `delete-tag`, — и там опции быть
  не должно (парность проверяет `tests/s2ctl/test_cli_tree.py`).
- **Неожиданный отказ не печатает трассировку:** внутри команды его ловит
  обёртка `S2CTLCommand`, вне команды (разбор конфигурации, колбэк параметра) —
  перехват в `run_cli`. Признак отладки — `DEBUG_MODE` из `s2ctl.click`,
  контекст вызова, а не `ctx.obj`.
- **HTTP только в `ssclient`.** В `cmd_*` нет ни запросов, ни разбора ответа;
  `ssclient` не импортирует `s2ctl`.
- **Состояние задачи — из `resources[]`**, а не из legacy-полей `server_id`,
  `nic_id` и подобных: у VMware-задачи их нет вовсе.
- **Тест живёт у владельца артефакта:** метод клиентского слоя — в
  `tests/ssclient/**` (локальный `aiohttp`-сервер из `tests/conftest.py`: метод,
  путь, payload, разбор ответа), состав дерева и разбор аргументов —
  в `tests/s2ctl/**`. Тесты форматтеров не пишутся; текст справки тоже
  не проверяется — проверяется её наличие: `tests/s2ctl/test_cli_tree.py`
  обходит дерево и требует описание у команды и `help` у опции.
- **Имя команды приводится к операции, которую она вызывает.** Потребителей
  у CLI нет, поэтому переименование команды или опции — обычное изменение,
  а не эскалация; каждое такое изменение попадает в README, в раздел
  «Some commands of the previous releases behave differently now».
- **Гейт стиля покрывает и `tools/`:** инструменты сопровождения — часть
  контекста, и `make lint` гоняет `flake8 src tools`.
- **Новое подавление в `.flake8` или `pyright` — с обоснованием рядом**, в том же
  комментарии, что и остальные записи `per-file-ignores`. Исключение —
  построчные `# noqa: WPS110` в `ssclient/**`: поле `value` доменных обёрток
  (`*Id`, `Tag`) несёт разобранное значение идентификатора и другого имени
  не имеет, обоснование у них общее и повторять его в каждой строке не нужно.
